# 基于演示与对象参照轨迹的 Astra 低频闭环操作

更新日期：2026-10-04

本项目研究如何让 Astra 从少量演示中理解操作方式，针对当前任务规划可执行轨迹，并由快速感知、执行和监控回路持续完成操作。目标是在保持任务完成能力的同时，减少 Astra 的推理次数、无效试探和总体完成时间。

本文件描述当前项目思路及职责边界。首轮演示交付形式已经形成协议；轨迹接口、功能关键点定位和异常监控尚需设计与验证，本文不表示这些能力已经实现。

首轮演示数据的制作与交付遵循[演示数据处理与交付协议](demostration_protocol.md)。

## 研究目标

现有仓库已经提供 Astra 在线观察、工具调用、EEF 控制和原生评测的基础设施。项目希望在此基础上，将 Astra 的决策单位从短时 EEF 修正提升到可执行的操作阶段。

Astra 在操作开始前利用任务信息、当前观察和演示，用语言描述任务执行的大致流程。初版每次只规划一个 Interaction Turn 的动作段，不预先生成整个任务的数值轨迹。

初版采用段间闭环：Astra 规划一个动作段，执行器执行并返回新观察，Astra 判断实际结果后重新规划下一段。动作段的内容、边界和长度由 Astra 按任务选择。完整定义与职责边界见 [Interaction Turn 设计](interaction_turn.md)。

后续目标是在执行期间由快速回路根据观测修正轨迹并判断明显异常，当当前计划不再适用或需要新的高层判断时，再调用 Astra 重新规划。实时视觉伺服与自动异常触发暂不作为初版已经具备的能力。

演示通过 in-context learning 提供操作经验，帮助 Astra 学习接近方式、运动形状、接触策略和阶段顺序。深度和三维几何信息用于将学习到的知识迁移到实际场景。两者共同支持较长的有效执行，提高轨迹预测精度，而不是依赖 RGB 反馈进行 trial-and-error 来修正 EEF。

项目的研究假设是：Astra 可以从演示中迁移操作范式，并将足够明确的轨迹交给快速回路，使高层推理保持低频，同时保留持续闭环反馈。该假设需要实验验证。

## 系统职责

系统包含以下职责，它们不必分别对应独立模型：

- 演示处理与交付：把原始演示组织成 Astra 能理解和迁移的分阶段参考。
- Astra 规划与判断：描述任务流程，选择操作对象与功能部位，每次规划一个 Interaction Turn 的动作段，并根据执行后的观察判断结果、重新规划下一段。
- 动作段执行：将当前动作段转换为底层控制命令，记录实际执行状态并返回段尾观察。
