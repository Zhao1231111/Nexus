# Interaction Turn：按操作段观察与重新规划

更新日期：2026-10-04

## 初版目标与范围

初版采用分段执行、段间观察与重新规划。Astra 在任务开始时用语言描述大致执行流程，之后每次只规划一个 Interaction Turn 的动作段。动作段执行结束后，Astra 根据新的实际观察判断结果，再规划下一段。

本文件记录当前确定的控制组织方式，不表示执行代码、实时视觉伺服或自主异常检测已经实现。演示与深度输入的设计遵循现有演示协议，其效果后续独立验证。

## Interaction Turn 的定义

一个 Interaction Turn 包含：

1. Astra 读取上一次 Interaction Turn 的执行结果，根据当前观察规划一个动作段；
2. 执行器执行该段，并记录实际执行回执；

执行后的观察与回执作为下一次 Interaction Turn 的输入。上一段的结果判断与下一段的规划在同一次 Astra 决策中完成，不在两段之间额外调用 Astra。第一次 Interaction Turn 使用任务初始观察，没有上一段执行结果。

这是一段机器人交互的逻辑单元，不等同于 Codex app-server 的模型 turn，也不等同于一个物理控制步。一个持久化模型线程可以包含多个 Interaction Turn。

## 任务流程与每段规划

任务开始时的语言流程描述操作顺序和预期目标，例如接近物体、下降并闭合夹爪、验证抓取、搬运、放置与释放。该流程是后续规划的参考，可以根据实际执行结果修改；不要求在任务开始时生成全部数值轨迹。

每次规划都以最新确认的实际状态为起点。Astra 自行决定下一段的操作内容、结束位置与长度，例如把一段完整自由空间运动作为一段，或把下降与夹爪闭合组织成一段。两段之间不能跳过实际发生的动作，也不能假定上一段达到了计划终点。

Interaction Turn 的动作段没有固定的控制步数或固定 waypoint 数量。长度随任务、运动距离和所需观察时机变化；执行仍受原生 episode 剩余步数和底层运动限制约束。

动作段的结束应尽量选在新的观察能够帮助决定下一步的位置。接近、接触和释放附近通常需要更密集的观察；自由空间运动可以使用更长的段。

## 执行完成与操作成功

执行器返回的“动作段执行完毕”仅说明命令执行或运动到位，不等于该段操作成功。

例如，下降并闭合夹爪可以作为一个动作段，但其段尾只能确认实际末端与夹爪状态。是否已经夹住物体，仍由下一次 Interaction Turn 的 Astra 根据观察结果判断，并触发重新规划。

每个段尾至少保留当前观察、实际末端状态、实际夹爪状态、已执行的控制步范围、执行是否完成，以及原生环境是否结束。

原生 success、terminated 与 truncated 仍由模拟器判定。模型对操作结果的判断用于控制决策，不替代原生评测。

## 路径表达与执行时序

Astra 初版负责规划几何路径（path），执行速度、加减速与控制周期下的时间参数化由底层规划器承担。路径进度参数 \(s\) 不表示时间；底层选择 \(s(t)\)，将路径变成实际执行轨迹。需要 Astra 规划速度或其他动态行为时，再讨论更复杂的接口。

保留以下三类模型输出形式。第二类与第三类都描述指定几何路径，可以共用底层处理，但对 Astra 而言是不同的表达入口。

### 第一类：点到点（PTP）

Astra 指定需要依次到达的目标 pose，不规定相邻点之间的具体几何路径，连接方式由下层决定。这类路径主要用于自由空间运动，底层可以使用 moveJ 等方式实现。

第一类的语义是“依次到达这些点”。若上层要求末端或 active 沿笛卡尔直线移动，应归入第二类，而不是把该要求隐含在 PTP 中。

### 第二类：数学函数路径

Astra 用参数化函数描述 active 相对于 target 的指定几何路径。完整位姿路径记为：

\[
{}^{B}T_A^{*}(s)=\bigl(R(s),p(s)\bigr),\qquad s\in[0,1].
\]

其中 \(A\)、\(B\) 分别是 active 与 target 的功能参考系，\(p(s)\) 描述位置，\(R(s)\) 描述姿态。姿态可以保持不变，也可以随路径变化；位置固定、只改变姿态的运动仍属于这一类。

直线、圆弧、绕轴旋转等常用几何运动可以通过相应参数描述，特殊形状可以使用自定义函数。底层负责沿路径插补与安排执行时序。

### 第三类：有序离散 pose 路径

Astra 直接输出有序的几何 pose，由底层按照明确约定连接和插补。与 PTP 不同，这些点用于描述需要保留的路径形状，下层不能任意重新选择点之间的连接路径。

离散 pose 是路径点，不默认每一项占用一个控制周期，点数和点间距离也不直接规定速度。它与 RoboICL 式逐控制步动作序列在时序含义上存在区别。

处理过程可以理解为“离散路径点 → 定义点间插补 → 按执行时序产生控制指令”。中间的连续路径是插补在数学上的含义，不要求显式生成并保存一个连续函数。Astra 输出的点也不必采样自某条既有曲线；插补本身可以定义这些点之间的路径。

位置分段直线、姿态在相邻点间插值，是一种易于理解的候选语义；具体插补规则尚待确定。连续不等于平滑：严格保留折线与允许圆滑过渡具有不同的几何含义。若允许平滑或近似，需要明确可以修改路径的范围与允许偏差，不能在下层隐式改变上层意图。

### 样条、路径组合与夹爪事件

样条不作为初版必须暴露给 Astra 的独立输出类型。直接选择有空间含义的 pose、方向、圆心和旋转轴，更容易将操作意图与观察关联；样条控制点通常不等于经过点，额外引入阶数、节点等参数会增加间接推理。该选择是接口设计判断，尚不代表已经验证过 Astra 对不同表达的实际能力。

样条可以作为后续可选的函数表达或底层插补方法，使用时仍需遵守路径形状与偏差约定。

一个 Interaction Turn 可以包含多种有序路径片段，例如“PTP 到准备位置 → 沿直线下降 → 到位后闭合夹爪”。夹爪开闭等操作事件应附着在明确的路径点或片段边界。经过某点、在该点停下、在该点触发操作是不同语义；这些动作顺序仍由上层表达，不交给底层速度规划猜测。

## Active、Target 与对象参照路径

- **Active obj**：当前阶段中，轨迹所描述的运动或作用主体，可以是夹爪、手持工具或被抓持的物体。允许夹爪／EEF 本身成为 active。
- **Target obj**：描述 active 相对运动时所参照的对象，通常也是当前操作的作用对象或放置对象。

对象参照路径描述 active 相对于 target 的位置、姿态或功能部位关系如何变化。上层控制对象语义由 active 与 target 决定；下层最终执行的 EEF 目标由这些对象关系转换得到。

## 完整功能参考系的定义

进入位姿变换计算的对象必须有完整的功能参考系。只提供一个点或一个点加轴向，不能直接代入完整位姿的矩阵乘法。

“只估计任务需要的自由度”意味着：任务相关的方向通过观察确定，其余方向通过明确约定补全，得到完整的计算参考系。补全的方向不表示已经观测到了物体的真实朝向。

例如，对于没有把手的圆柱杯，可以通过观察确定杯口中心 \(p\) 和指向杯口的单位轴向 \(z\)。选取一个不平行于 \(z\) 的已知参考方向 \(r\)，构造：

\[
x=\frac{r-(r^\top z)z}{\lVert r-(r^\top z)z\rVert},
\qquad y=z\times x,
\qquad
T=\begin{bmatrix}x&y&z&p\\0&0&0&1\end{bmatrix}.
\]

其中原点与 \(z\) 来自几何观测，\(x,y\) 来自约定。若参考方向与轴向平行，应选择其他不平行的方向，不能使用退化的构造。

参考系应定义在任务功能部位上。例如，杯子的参考可以使用杯口中心、轴向与把手方向；工具可以使用工作端与工作轴；托盘可以使用目标区域中心、表面法向与长边方向。

参考系的语义、原点、轴向定义以及观测与约定的来源需要记录，并与演示中的定义保持可解释的对应。同一个参考系不能在后续观察中静默改为另一套原点或轴向。

尤其是 active 的参考系：在抓持标定时完成定义后，它应固定在 active 上，通过 active–EEF 关系传播。不能每帧重新使用世界方向补全它，否则计算参考系可能相对于物体旋转，使固定抓持变换失去原有含义。

如果后续选择只输出位置、轴向等部分约束，下层需要求解满足约束的 EEF pose，不能再仅靠下述矩阵乘法直接得到唯一目标。初版保留完整功能参考系与完整位姿路径的接口。

## 对象路径到 EEF 目标的转换

定义 \({}^{X}T_Y\) 为 Y 坐标系在 X 中的位姿，即将 Y 坐标表达转换到 X。使用以下参考系：

- \(W\)：统一的世界／环境参考系；
- \(B\)：target 的功能参考系；
- \(A\)：active 的功能参考系；
- \(E\)：底层控制所使用的 EEF 参考系。

Astra 规划 \({}^{B}T_A^{*}(s)\)。已知 target 在世界中的估计位姿 \({}^{W}\hat T_B\)，以及 active 相对于 EEF 的估计变换 \({}^{E}\hat T_A\) 后，下层计算：

\[
{}^{W}T_E^{*}(s)
=
{}^{W}\hat T_B\;
{}^{B}T_A^{*}(s)\;
\left({}^{E}\hat T_A\right)^{-1}.
\]

对于 PTP，只需在相应目标 pose 上进行转换；对于函数或离散 pose 路径，应在指定路径上进行转换并保留其几何语义。

若 active 就是底层 EEF，且采用同一个参考系，\({}^{E}T_A\) 为单位变换。若 active 是夹爪的功能参考系，应使用明确已知或经过标定的夹爪–EEF 变换。link6、TCP 与功能点不能未经定义就视为同一个控制参考系。

该转换适用于 EEF／夹爪直接作为 active，或 active 与 EEF 存在有效刚性连接的情况。被释放的物体不能继续按固定 active–EEF 关系传播和控制。

人为补全的坐标轴可以进入计算，前提是规划路径与抓持变换使用同一套定义。例如，将 active 的参考系改为 \(A'\)，令固定变换 \(Q={}^{A}T_{A'}\)，则两项都应相应变化：

\[
{}^{B}T_{A'}^{*}={}^BT_A^{*}Q,
\qquad
{}^{E}T_{A'}={}^ET_AQ.
\]

它们在执行转换中抵消：

\[
{}^{B}T_{A'}^{*}\left({}^{E}T_{A'}\right)^{-1}
=
{}^{B}T_A^{*}\left({}^{E}T_A\right)^{-1}.
\]

因此，一致的坐标系选择不会改变实际运动；只改参考系定义而不更新相应路径与变换会改变执行结果。

## 关键时刻定位与抓持标定

初版不要求每帧准确识别 active、target 并重建对象参考系，而是利用以下两个前提：

1. target 在当前操作段内近似静止，因此可以绑定 Interaction Turn 开始时的几何估计；
2. 有效刚性夹持期间，active 相对于 EEF 的位姿近似固定。active 仍在世界中运动，其位姿由实际 EEF 状态传播。

Astra 负责识别对象、选择语义部位、定义功能参考系并判断观察是否充分；几何工具利用 RGB-D、相机标定与同步机器人状态计算 metric 位姿。不能将模型对图像的直观坐标猜测当成已经测量到的几何信息。

形成抓持后，可以安排主动观测，将 EEF 与抓持物体移动到便于观察的位置。该动作既用于确认物体是否被带起，也用于估计此次实际建立的 active–EEF 关系，而不是沿用演示中的抓取偏移。

在观测时刻 \(t_g\)，使用同步的实际 EEF 位姿与 active 几何估计计算：

\[
{}^{E}\hat T_A
=
\left({}^{W}T_E(t_g)\right)^{-1}
{}^{W}\hat T_A(t_g).
\]

之后，在刚性连接前提成立时，可以通过本体状态传播：

\[
{}^{W}\hat T_A(t)
=
{}^{W}T_E(t)\;{}^{E}\hat T_A.
\]

主动观测应以获得清晰且足够的功能部位观察为目的。若原位已经可见，可以原位估计；若存在遮挡，可以面向固定 head camera 或其他具有独立视角的相机移动，必要时使用多个视角。若腕部相机与 active 都固定在同一个 EEF 上，移动整个手臂不会改变二者的相对视角，不能依赖这种移动解除相同的几何遮挡。

主动观测本身可以构成一个 Interaction Turn，由下一轮 Astra 读取其结果，确认抓持关系并规划后续运动。

## 估计的有效范围与段间反馈

target 静止与 active–EEF 刚性连接是两个独立前提，不是永久成立的事实。target 被碰动时，其世界位姿可能失效；active 在夹爪中滑移或转动时，抓持变换可能失效。释放、重新抓取或交接到另一只手后，应重新建立相应关系。

已经可靠建立的估计可以在前提仍成立时跨多个 Interaction Turn 复用，不需要每轮重新定义参考系。复用时应绑定具体对象、功能参考系定义与当前抓持关系；下一轮观察发现前提变化时，更新相应估计。

一次清晰观测不能保证之后永不滑移，也不能自动保证满足任务精度。需要保存用于计算的关键点、构造定义与观测时刻，并结合几何可观测性判断估计是否充分。长工具的工作点尤其受方向误差影响，因此只提高图像可见性不能替代姿态精度的验证。

两次对象观察之间，初版依据静止与刚性连接前提传播位姿，不具有持续对象视觉伺服；机器人运动可以继续使用本体状态反馈。下一次 Interaction Turn 开始时，Astra 根据实际观察判断上一段结果并重新规划，从而形成对象反馈较稀疏的段间闭环。

## 执行职责与未实现能力

执行器负责把当前动作段转为可执行控制命令，并按照最新机器人状态进行底层运动跟踪。初版不在段内使用对象视觉反馈修正操作，也不假定已有通用异常识别器。

正常情况下，动作段结束本身就是再次观察与调用 Astra 的触发点。因此初版无需依靠自动异常检测，才能建立段间的纠错与重新规划机制。

若执行器明确确认运动未完成，应返回实际停止状态供 Astra 判断；若物理调用的回执不确定，沿用当前仓库的无自动重放规则，不能把它当成尚未执行的动作再次发送。

## 初版的研究定位

这个组织方式与可变长度 action chunk 有明显重合。初版主要建立可运行的实验基础：让 Astra 按操作内容选择执行段与观察时机，并在每次段尾根据实际结果重新规划。

效果需要与相同观察、演示和几何输入下的短段执行比较。重点观察成功率、Astra 调用数、实际控制步数、总耗时，以及不同段长下错误被发现的时机。不能仅凭段长增加就认定闭环能力或方法优势已经提升。
